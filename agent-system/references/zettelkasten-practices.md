## Applied to this project

- Root entrypoints route to one visible folder. [PROJECT.md](../PROJECT.md)
  preserves Reflect's existing product/architecture/convention guide; workflows
  add fork execution practices without replacing deeper technical owners.
- Plans expose consequential choices and reasons. Acceptance describes a trigger,
  observable result, and failure cases. Candidate guidance was adapted as a small
  planning aid, not adopted as a complete external methodology.
- Handoffs retain accepted scope, failed attempts, important rejected options,
  source revision, current evidence, and the next useful action. Retrieval remains
  bounded; no new memory store or blanket compaction policy was introduced.
- [Validation](../workflows/validation.md) ties claims to the inputs checked and
  invalidates affected evidence when those inputs change.
- [Learning](../workflows/learning.md) connects a concrete failure to the owning
  layer, regression evidence, a scoped improvement, and reviewable results.

task-system references were not imported; this repository remains independent of
the vault and Operating System. No provider, model, external skill package,
dashboard, runtime hook, personal graph, or paid service was adopted. Headroom
remains prohibited by current parent instructions regardless of older examples.

The recommendations are justified as modest project practices, not as measured
productivity gains. Local source review does not verify every upstream paper,
product claim, or current external repository. Use live technical sources for
future implementation decisions.
